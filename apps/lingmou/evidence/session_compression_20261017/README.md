# 会话级压缩与缓存前缀稳定性（2026-10-17，源码改动，未发布）

## 起因

0.1.7 的真实 Windows 连续读取测试（`../windows_compression_coverage_20261017/real-windows-report.json`）中，
旧工具输出开始归档后，官方缓存命中从约 19k 回落到 12,544 并保持不变，每次请求未命中的输入由约 3k
升至 12k–14k。原因是每个请求都重新决定旧历史的发送形式：选段依赖当前任务，归档每轮多一条，
请求前部一变，后面的缓存全部失效。本地“缩减率”没有计入这部分损失。

## 改动

- `src/codexscope/session_compression.py`：按对话保存每条历史第一次发送时的形式，以及指令和工具定义的形式，
  之后原样复用，发送内容只在末尾追加。旧内容的有损处理只在“集中整理”时进行：工具输出超过 40k 本地估算
  token 时一次压到 12k；旧截图累计 3 张以上；上下文超过 96k 时整轮归档旧对话。每次整理前比较
  “打断缓存的一次性成本”和“后续请求的预计节省”，不划算就推迟；连续观察到服务商没有缓存时，成本按 0 计。
  另记录每个请求与上一请求的前缀在哪里分叉，以及分叉由灵眸还是客户端引起。
- 集中整理时新增：同一命令再次执行或文件之后被修改时，较早的输出改为可补读的 `superseded/v1` 提示；
  保留最近 2 张图片和最新用户消息中的图片，其余替换为文字说明（图片本身不能通过补读恢复）；
  归档提示额外保留含 error/FAILED/Traceback 等词的行。大段补丁参数归档仍为可选项
  （`LINGMOU_SESSION_ARCHIVE_TOOL_CALL_INPUTS=1`），默认关闭。
- 新工具输出到达时做确定性清理：去掉 ANSI 颜色、进度条中间帧和连续重复行（注明重复次数）。
- 8 MiB 限制只按文本计算，内联图片不再使整个请求跳过压缩；整请求估算不再计入图片 base64 和加密推理。
- 整轮历史归档允许包含 reasoning 条目（随所属回合一起移除）。
- 桌面页面新增缓存命中率、未命中输入、等效计费输入（未命中 + 命中 × 0.1，
  可用 `LINGMOU_CACHE_PRICE_RATIO` 调整）、按官方输入校准的本地估算，以及每个请求的缓存前缀状态。

## 离线回放（缓存模型估算，非官方用量）

`scripts/replay_cache_economics.py` 把同一组逐步增长的请求分别交给改动前源码（`v0.1.7`，本次修改前的工作区副本）
和改动后源码（`session`），并按“与上一请求共享的条目前缀视为缓存命中、命中按 0.1 计价”估算。
两者都使用 full 模式、仅本地，不调用模型，也不评价回答质量。

| 回放 | 变体 | 输入合计 | 未命中合计 | 等效计费输入 |
|---|---|---:|---:|---:|
| 论文任务可见历史，21 次请求 | 不压缩 | 870,136 | 66,588 | 146,944 |
| | v0.1.7 | 578,445 | 149,704 | 192,578 |
| | session | 844,297 | 99,037 | 173,565 |
| 同上，再追加 20 次小工具请求 | 不压缩 | 2,320,436 | 77,607 | 301,893 |
| | v0.1.7 | 1,496,055 | 161,503 | 294,957 |
| | session | 1,786,407 | 110,836 | 278,394 |
| 合成编码循环，37 次请求 | 不压缩 | 2,213,949 | 108,372 | 318,929 |
| | v0.1.7 | 568,673 | 150,628 | 192,432 |
| | session | 988,567 | 84,905 | 175,271 |

- 在这个缓存模型下，v0.1.7 在论文回放中的等效输入比不压缩高 31%：缩减了输入，却反复打断缓存。
- session 版本只在最后一次请求做了一次集中整理，所以 21 次请求的回放只体现了打断缓存的成本；
  追加 20 次请求后，等效输入比不压缩低 7.8%，比 v0.1.7 低 5.6%。
- 合成数据专门构造了重复读取、修改后过期、测试重跑和终端噪声，用于检验策略，不代表真实节省比例。
- 回放缺少真实请求中的工具定义、指令、图片和加密推理，只是可见历史。

文件：[论文回放](paper-cache-replay-extend0.json)、[追加 20 次](paper-cache-replay-extend20.json)、
[合成回放](synthetic-cache-replay.json)、[合成数据](synthetic-replay.json)、[生成脚本](make_synthetic_replay.py)。

复现（`OLD_SRC` 为改动前源码的 `src` 目录）：

```bash
.venv/bin/python scripts/replay_cache_economics.py \
  evidence/windows_compression_coverage_20261017/paper-visible-replay.json --extend 20 \
  --variant v0.1.7=$OLD_SRC --variant session=src
```

## 最大压缩模式（`max`，实验）

以压缩率为先，不考虑缓存成本。在 full 的基础上：

- 工具说明：按小节缩短 code mode `exec` 等长描述，保留 TypeScript 声明（去掉注释），说明文字改为补读指针
  （`src/codexscope/header_compression.py`）。补读工具自身的定义不改。
- 指令：Codex 提示词中关于语气、进度汇报和最终回答格式的小节改为补读指针；任务、安全、沙箱、AGENTS.md 和工具规则不动。
  技能目录只保留被明确点名的技能说明，其余保留名称和路径。
- 历史：工具输出（含长调用参数）超过 6k 即整理到 2.5k，保留最近 2 个结果；上下文超过 24k 即整轮归档到 12k，
  只保留最近 1 轮；只保留最新 1 张截图；长度 ≥1,200 字符的旧调用参数（脚本、补丁）也归档。不做缓存成本判断。

真实请求头取自本机 Codex 0.162.1（code mode + 本机技能目录），通过临时 `CODEX_HOME` 和本地抓包服务获得，
未调用模型；历史条目取自本机两个 Codex 会话（rollout，第一次 Codex 自动压缩之前的部分）。
会话内容和请求头属于本机私有数据，未放入本目录；`replay-real-*.json` 只含逐请求数字。

| 回放（全部为本地估算） | 变体 | 输入压缩率 | 未命中合计 | 等效计费输入（与不压缩比） |
|---|---|---:|---:|---:|
| 真实会话 A，167 次请求 | v0.1.7 | 40.2% | 786,012 | −16.2% |
| | full（新） | 52.7% | 345,363 | −44.0% |
| | max | **69.4%** | 272,584 | −62.0% |
| 真实会话 B，147 次请求 | v0.1.7 | 45.2% | 1,121,925 | −5.2% |
| | full（新） | 47.0% | 342,253 | −38.4% |
| | max | **85.0%** | 251,696 | −76.3% |

最后一次请求的组件对比（max，会话 A / B）：工具返回减少 93% / 98%，工具调用参数 76% / 97%，旧对话 84% / 93%，
指令 44% / 44%，工具定义 26% / 26%。最终请求中的补读指针 31 / 11 个，全部可取回原文。

**局限**：回放不让模型实际运行，因此不包含模型因信息被归档而发起的补读请求，也没有评价回答质量和任务成功率；
回放中的会话是较早版本 Codex 的历史，配上当前版本的请求头。max 会让模型更依赖补读，最终回答格式也可能变化，
真实任务中的净效果必须用官方 usage 与任务结果确认。

复现（本机数据）：

```bash
.venv/bin/python -I scripts/rollout_to_replay.py ~/.codex/sessions/.../rollout-....jsonl /tmp/real.json \
  --header CAPTURED_REQUEST.jsonl
.venv/bin/python scripts/replay_cache_economics.py /tmp/real.json \
  --variant v0.1.7=$OLD_SRC@full --variant full=src@full --variant max=src@max
```
