# 灵眸 0.1.8 · 按对话保持缓存，新增最大压缩（实验）

## 按对话保持缓存前缀

模型服务的输入缓存只对完全相同的请求前缀生效。旧版每次请求都重新压缩整段历史，已发出的内容写法一变，
后面的缓存全部失效；0.1.7 真实测试中，归档开始后缓存命中下降，压缩后未命中的输入反而增加。

- 同一对话中，每条历史、指令和工具定义第一次发送后，后续请求原样复用，只在末尾追加。换任务不再改写已发出的内容。
- 旧工具输出、旧截图、整轮旧对话改为超过水位线时集中整理一次（完整压缩：工具输出 40k→12k、上下文 >96k）；
  整理前比较打断缓存的成本与后续节省，不划算则推迟。被之后同一命令或文件修改取代的旧输出优先归档，归档提示保留报错行。
- 新工具输出去掉颜色代码、进度条中间帧和连续重复行。内联图片不再使整个请求因 8 MiB 限制跳过压缩；
  本地估算不再计入图片 base64 和加密推理。
- 用量页新增缓存命中率、未命中输入、等效计费输入（未命中 + 命中 × 0.1）、按官方输入校准的估算，
  以及每个请求的缓存前缀状态。是否省钱请看等效计费输入，不要只看本地缩减率。

## 最大压缩（实验）

新增“最大压缩”模式，以压缩率优先、不考虑缓存成本：缩写长工具说明和回答风格指令（可补读），技能目录只保留被点名的说明，
更早归档旧工具输出、旧脚本与补丁参数和旧对话，只保留最新截图。文字原文均可补读；旧截图不可恢复，回答格式可能变化。

在本机两个真实 Codex 会话的离线回放中（本地估算，不含模型补读和回答质量），输入压缩率：
0.1.7 为 40.2% / 45.2%，完整压缩为 52.7% / 47.0%，最大压缩为 69.4% / 85.0%。
这些结果**尚未在真实 Windows 与 Codex 上验收**，真实收益需以官方 usage 和任务结果确认。
详见 `evidence/session_compression_20261017/`。

## 0.1.7 · Windows 10/11 x64

完整压缩增加同一用户回合内的旧工具输出归档，适用于读论文、读代码、生成文件等连续调用工具的长任务。

- 工具输出累计超过 12,000 个本地估算 Token 时，将较早的大段输出存入原文库，用首尾预览和补读指针替换；最近 4 个工具结果不参与这一步归档。
- 这一步归档跳过失败信息、AGENTS/SKILL 文件读取和原文补读；原有其他压缩步骤仍按原规则执行。工具调用参数、调用配对、系统与用户指令、图片及不透明推理字段不因本次归档而改写。
- 来源工具不可用、原文库配额不足、单行过长无法补读或调用配对不明确时，保留原输出。
- 保留 0.1.6 的当前对话统计规则。压缩率仍是当前会话请求的本地估算，不是官方费用节省率。

Windows 真实 Codex 连续读取测试：10 次请求的本地输入估算缩减 19.96%，包括一次归档原文补读，答案核对通过。另对论文任务可见历史作相同输入的离线回放，缩减为 33.57%，旧逻辑为 0.38%；该回放不含完整工具定义。这些结果不是费用 A/B 测试，也不代表所有任务的收益。远程验证与安装状态见 `evidence/windows_compression_coverage_20261017/`；本地打包不代表已上传 GitHub Release。

已安装 0.1.7 的远程 App 在原 PPT 会话追加只读核对：升级后两次请求共 290,400 → 232,810 个本地估算 Token，界面显示 19.8%，工具返回部分减少 55.36%。答案核对通过，原 PPT 和报告文件哈希未改变。这是追加任务的结果，并非重算之前整次 PPT 制作的压缩率。

## 0.1.6 · 按当前对话统计（继续保留）

Token 用量从当前对话的新请求开始计算，不再混合多个对话或显示上次后台的累计记录。

- 对话开始前隐藏用量卡片，显示「等待对话开始」；初始化和预热请求不触发统计。
- 新对话首个实际请求到达时，压缩前后、节省量、官方用量、组件和请求列表同步重新累计。
- 同一对话继续累计；旧回合迟到的回复和工具请求不混入新对话。切到其他对话再返回，从新回合重新统计。
- 重启后台等待新的请求，切换压缩方式保留当前对话的统计。

统计切换以实际请求为准；仅打开 Codex 空白页时，代理无法观察界面焦点变化。新请求携带的历史上下文仍计入该次输入。
