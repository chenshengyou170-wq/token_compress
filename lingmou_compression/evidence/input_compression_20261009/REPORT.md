**灵眸输入压缩：仓库分析、实现与真实上游对照（2026-10-09）**

这是灵眸产品的输入压缩实验，不是独立的多模态/隐藏 Token 调研验收。默认关闭；尚未提交或发布。

当前英文/中文材料中，没有一组同时达到官方输入减少 30% 且全部答案检查通过。建议先按任务验证本地 hybrid；Kimi 文本改写仍保留为实验选项，不能作为无损压缩上线。

**两个仓库怎样节省 token**

Caveman 对自然语言做简写。LLM 版把自然语言分句调用 GPT-4o-mini，默认还计算原文/改写的 embedding；NLP 版删除 spaCy 停用词，不能据此保证否定关系；MLM 版按 RoBERTa 的可预测性删词。源码里的 token 计数主要是字符数除以 4。其事实基准仅 2 篇、13 条事实，报告平均字符缩短 18.6%；README 的 40–58% 不代表任意真实请求均能达到。来源：[LLM 源码](https://github.com/wilpel/caveman-compression/blob/2a11efbf74863449e3392322ea0bf8d7ebe55357/caveman_compress.py)、[NLP 源码](https://github.com/wilpel/caveman-compression/blob/2a11efbf74863449e3392322ea0bf8d7ebe55357/caveman_compress_nlp.py)、[事实基准](https://github.com/wilpel/caveman-compression/blob/2a11efbf74863449e3392322ea0bf8d7ebe55357/benchmark/factual_preservation/README.md)。

另用 o200k_base 对仓库现成示例重新分词：系统提示词 113→51（54.87%），API 文档 99→57（42.42%），简历 153→126（17.65%）；三项合计减少 35.89%。这只是现成文本的本地重计数，没有证明重写质量，也没有计入完整 Agent 请求开销。记录：[示例重计数](upstream_examples_recount.json)。

GenericAgent 主要减少发送的上下文：压缩旧消息里的标签内容、限制工具结果长度，超阈值后淘汰旧历史，并用工作快照、key_info 和分层记忆按需恢复信息。默认标签保留最近 10 条，旧标签截取首尾合计约 800 字符；历史阈值按字符计算，常规目标保留 60%。它的整套 Agent 效率比较同时包含工具、轮数、记忆与调度差异，不能当成可单独移植的压缩模块效果。来源：[上下文实现](https://github.com/lsdefine/GenericAgent/blob/f308ee7eb079cc402edf5a934fa65f6d71a4c7ad/llmcore.py)、[项目评测说明](https://github.com/lsdefine/GenericAgent/blob/f308ee7eb079cc402edf5a934fa65f6d71a4c7ad/README.md#-evaluation)。

**当前接入**

在 RequestTokenTap 转发实际请求前处理文本。hybrid 使用本地简写、保护片段、相同工具结果引用、JSON 空白整理；kimi 在此基础上调用 Kimi 改写，优先处理任务材料。保护项必须完整且保持顺序，文本和本地估算都变短才采用；失败时回退原文。保留工具协议对象、代码等受保护材料，没有实现 GenericAgent 的长程历史淘汰与记忆架构。具体用法见 [README](../../README.md#codex-输入侧压缩实验功能)。

每个请求记录压缩前/后本地估算及该请求返回的官方 usage。GPT 使用已有 ChatGPT 登录的 Codex，同时核对代理捕获的 SSE usage 与 Codex turn.completed；Kimi 使用官方 Kimi Code Chat Completions。两类接入的固定提示词开销不同，模型之间的绝对输入数不能直接比较。本地 o200k_base 替代计数不是 GPT-6/Kimi 官方计数，也不是预计算接口的精确值。

**测试口径**

四个下游模型 × 三个材料 × off/hybrid/kimi × 两次调用，计划 72 次。两次下游调用会复用已接受的 Kimi 改写缓存，不是两次独立压缩采样；失败改写有 5 分钟退避。英文 8 项、中文 16 项、合成长文 8 项，不同模型也可能遇到不同缓存/重试状态，所以这里比较的是实际接入流程，不能据此给模型能力排名。按固定 JSON 值、类型及字段集合检查；通过不等于普遍语义等价。顺序在第二次反转。本轮所有 LLM 压缩均使用 kimi-for-coding，按要求从节省比例分母和分子中排除；另存 compression_calls。超时压缩调用可能缺少官方 usage，不能据此计算完整净费用。

当前已记录 72 次，其中 71 次完成，1 次调用失败。失败的质量检查也保留在表中，不因不通过而剔除。

**如何理解 30% 目标**

输入缩短比例取决于可处理材料占整个请求的比例。Codex 的系统提示词、工具定义和协议开销较大，只缩短短任务文字难以使整个请求下降 30%。中文业务资料的数字、条件、表格和代码密集，删去这些内容会破坏事实或边界。LLM 改写还受超时、保护项检查、格式稳定性影响。重复的大型工具结果更适合结构整理，但其合成测试收益不能推广为日常 Agent 的平均收益。

**验证和边界**

626 passed in 49.97s。另完成真实 GPT-6 工具往返：关闭与 hybrid 均正确调用一次只读 printf 并返回标记；每种模式实际产生两个上游请求，账本的 input/output/total 之和与 Codex 官方 turn.completed 完全一致。来源：[工具往返](tool_roundtrip/results.json)。

开发过程的失败保存在 pilot、guarded_pilot、bounded_pilot；bounded_pilot 有一次在途请求因修订策略被中断，未取得该次官方 usage。GPT-5.4 探测没有完成有效请求，正式 GPT-5 对照采用当前账号可用的 GPT-5.6 Sol。官方型号参考：[GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra)、[GPT-5.6 Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol)、[Kimi Code](https://www.kimi.com/code/docs/en/)。
